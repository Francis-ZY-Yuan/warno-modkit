WARNO build 211352 stopped every build at one gate: `ndfrules.check_exe` found an installed WARNO.exe other than
the one the rules table was read from. `setup extract` ran on the declarations as they are, and `ndfrules extract`
read the new exe. The reader now skips an object holding a code pointer: a check may load one before the strings it
passes, and the pointer's low bytes can read as a short string.

What changed for the stock corpus. The archive chain grew by one revision instead of being rebased: five revisions
(193438, 197351, 201602, 210942, 211352), 7,710 archives with 154,167 entries, all read. 211352 ships a delta folder
under 210942 and a top-level folder holding a full copy of every map, scenario and decor set `_Definition` pack,
the Cuban ones 210942 shipped in its delta folder included. Of the files a full extraction holds, 7 changed in
content: `NDF/UI/Components.txn` and its tag, and `CampagneStrat_Invasion_of_Cuba`'s script (GDScript with its tag and
`.dbg`), LevelDesign and items. Five other extracted scenario packs now come from the new folder, with the same
content. No declared file or folder is missing.

What changed in the load-time rules: nothing. The table holds the same 3,663 rules on 1,415 classes, row for row; only
the stock counts moved, on the UI component and script classes those two changed files hold. All 663 stock files of
211352 (1.56 million objects) pass. The fixed reader and the previous one give the same table on this exe.

The Cuba campaign's new script moved two stock counts the ops gate tests hold: six more union edges (69, so 2,845 in
all) and one more objective whose failure condition holds while a unit group is empty (17 such tests). The script
fills that group in an earlier step of the same Sequential, as stock does for the other 16, so the tests list it.

Packaging still writes 210942 into `Gen/Version.ndf` and `ModGenVersion`. A mod so stamped, Twin Strike's Workshop
copy, was active and played on 211352, so a mod one build behind is not switched off for it; whether the stamp must
follow the running build is still open ([[mod-version-and-config-lines]]).
