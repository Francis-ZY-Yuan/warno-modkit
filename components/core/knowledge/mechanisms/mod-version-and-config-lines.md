**What the game does.** The Mod Center lists a mod folder that holds only `Config.ini` and `Scenarios/` as
outdated, and an outdated mod cannot be activated. Add `Gen/Version.ndf` (one line naming the game build, as in
every current Workshop mod) and an empty `[Config]` section, and the same folder is active, with the scenario-type
icon. At startup the game rewrites the activated-mods line of your `mod\Config.ini`.

`[Config]` holds one `<cluster>=<md5>` line per game cluster the mod replaces: the md5 of the stock file it was
built against. When a game update changes that cluster, the hash stops matching and the mod is force-disabled as
outdated until it is rebuilt.

**Gotchas.**
- A scenario-only mod has an empty `[Config]`, so an update cannot make it outdated by hash. It does break when an
  update re-ships the stock scenario templates: the tags of its compiled transactions still hold the old build's
  source hashes, so the game compiles them from sources the mod does not ship, and the load stops at "File not
  found" for the mod's own `Scenario.ndf` ([[txn-tag-config-hash]], [[2026-11-18-build-212400-port]]). Its packs
  also depend on stock class schemas, map item GUIDs, dictionary tokens and cloned files. After each update:
  re-extract, rebuild, set the new build in `Gen/Version.ndf` and `ModGenVersion`, and play it again.
- Whether the value in `Gen/Version.ndf` must equal the running build is not known.
- Every Workshop mod pairs `Gen/Version.ndf` and `ModGenVersion` with the build that made it, across five builds up
  to 201602. Packaging follows that rule: it wrote 210942 from [[2026-11-12-build-210942-port]] and 211352 from
  [[2026-11-17-build-211352-port]], and writes 212400 from [[2026-11-18-build-212400-port]]. No mod generated by the
  game's own tools on 210942, 211352 or 212400 has been seen yet. Twin Strike, packaged with 210942, was active and
  loaded on 210942 ([[2026-11-12-twin-strike-210942-play1]]), and its Workshop copy, so stamped, was active and
  played on 211352 ([[2026-11-17-build-211352-port]]).
- On 210942 the Workshop upload rewrites the installed `Config.ini` without the empty `[Config]` section's header line
  (and without the `Description` and `CosmeticOnly` lines) ([[2026-11-12-twin-strike-workshop-upload]]). Whether the
  game still lists a mod with no `[Config]` section is unseen, so packaging keeps writing it.
- An upload made on a newer build stamps that build into `Config.ini`'s `ModGenVersion`, while `Gen/Version.ndf` keeps
  the build the mod was made for: the Workshop copy then no longer pairs the two lines. Twin Strike's update, uploaded
  on 212400's exe, pairs `Gen/Version.ndf` 211352 with `ModGenVersion` 212400
  ([[2026-11-18-twin-strike-workshop-update]]). The game kept that copy active on 212400, and its load stopped on
  stale transaction tags, not on the stamp ([[2026-11-18-build-212400-port]]).
